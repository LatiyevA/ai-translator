# AI Translator

Литературный перевод книг и фанфиков с китайского на русский. Переводчик может перестраивать предложения, диалоги и идиомы ради естественной русской прозы. Глоссарий задаёт привычные формы имён и терминов, а отдельный этап редактуры позволяет сверить черновик с оригиналом.

## Десктопное приложение

```bash
uv sync --locked --extra desktop
uv run --extra desktop ai-translator-desktop
```

Для запуска вне репозитория установите wheel как инструмент. Команда `uv build --wheel` создаст wheel в папке `dist`.

```bash
uv tool install "./dist/ai_translator-0.1.0-py3-none-any.whl[desktop]"
ai-translator-desktop "книга.epub"
```

Если `uv` сообщит, что каталог инструментов отсутствует в `PATH`, выполните `uv tool update-shell` и откройте терминал заново.

Выберите или перетащите книгу в окно. Затем выберите провайдера и действие. Можно собрать глоссарий, перевести небольшую двуязычную пробу или подготовить всю книгу. Кнопка «Оценить запросы» покажет план без расходования квоты.

Чтобы взять целую главу, выберите «Перевести пробу», нажмите «Загрузить оглавление» и выберите название. «Оценить запросы» рассчитает все пакеты выбранной главы. Вариант «По пакетам» позволяет выбрать диапазон вручную.

На вкладке «Проба» китайский оригинал и русский перевод показаны рядом. Кнопки листают фрагменты, а поле с номером позволяет перейти к нужной паре. Если включена редактура, переключатель показывает черновик, редакторскую версию или итог в файле. Для фрагментов, которые прошли сверку, видно, какую версию она выбрала. Переключение использует уже полученные ответы. Двуязычный TXT содержит итоговый текст. В открытом окне выбранный путь сохранения запоминается отдельно для каждой книги, действия и выбранной главы.

В строке «Последний запуск» кнопка «Восстановить» возвращает книгу, действие, выходные пути, диапазон пробы, глоссарий, модели, стиль, файл кеша и лимит на запуск. После ошибки записи или прерывания общий лимит можно восстановить в режиме «Ужесточить». Он сохраняет меньший из выбранного и действующего потолков. Чтобы повысить или снять действующий лимит, измените его явно. Проверьте параметры и нажмите кнопку выбранного действия, чтобы продолжить. Если выходной файл уже существует, приложение снова запросит подтверждение замены. Кнопка «Забыть» удаляет сохранённые параметры и сохраняет кеш и результаты.

Если вы начали работу в CLI с `--state`, укажите ту же базу SQLite в поле «Файл кеша». Оценка запросов покажет, какие ответы можно переиспользовать. При пустом поле кеш хранится рядом с исходной книгой. При выборе другой книги поле очищается.

На вкладке «Модели и стиль» для каждого этапа можно выбрать модель и reasoning из подсказок или ввести свои значения. «Авто» оставляет выбор reasoning провайдеру. Доступность моделей и уровней зависит от аккаунта, модели и версии клиента. На этой же вкладке можно сохранить профиль TOML и передать его CLI через `--config`. Путь к книге и лимит запросов на запуск задаются отдельно. [Модели Codex](https://learn.chatgpt.com/docs/models) · [Claude Code](https://code.claude.com/docs/en/cli-reference) · [Reasoning в OpenAI API](https://developers.openai.com/api/docs/guides/reasoning)

Кнопка «Редактировать глоссарий» открывает таблицу терминов. Укажите китайский оригинал, его варианты и общий русский перевод. Для обязательной формы поставьте флажок и при необходимости перечислите склонения. Варианты оригинала и склонения разделяются точкой с запятой. Сохранённый JSON автоматически подставляется для следующего запуска и подходит для `--glossary` в CLI.

«Проверить вход» проверяет текущую авторизацию. Для входа в подписочные провайдеры используются команды `codex login` или `claude auth login`. OpenAI API получает ключ из окружения. Кнопка «Остановить» прерывает обработку, при повторном запуске используются принятые ответы из общего с CLI кеша. Готовый файл можно открыть системной программой из окна переводчика.

Десктопная версия использует Qt. На минимальной установке Linux могут понадобиться системные библиотеки Qt для дисплея, включая EGL и зависимости XCB для X11, а также шрифт с китайскими иероглифами, например Noto Sans CJK.

## Быстрый старт

Нужны Python 3.11 или новее, uv и актуальный Codex CLI. Для подписочного режима войдите в Codex через ChatGPT. Перевод использует лимиты Codex вашего плана. [Установка uv](https://docs.astral.sh/uv/) · [Установка Codex CLI](https://developers.openai.com/codex/cli) · [Вход и лимиты Codex](https://developers.openai.com/codex/auth)

```bash
uv sync --locked
codex login status     # Если вход ещё не выполнен, запустите codex login.
uv run ai-translator translate "книга.epub"
```

Готовый файл появится рядом с исходным под именем `книга.ru.epub`. Флаг `--edit` включает отдельную редактуру, а `-o` задаёт путь результата.

```bash
uv run ai-translator translate "книга.fb2" --edit -o "перевод.fb2"
```

TXT, FB2 и EPUB сохраняются в исходном формате. Для TXT распознаются UTF-8, UTF-16 и UTF-32 с BOM, затем GB18030. При необходимости задайте `--encoding` явно. Выходной TXT записывается в UTF-8. FB2 сохраняет структуру, сноски и вложенные изображения. EPUB сохраняет порядок чтения, ссылки, оформление и ресурсы. В EPUB переводится китайский текст в XHTML, оглавлении и заголовках, включая доступные подписи ссылок и изображений, а также подписи и описания на страницах SVG и в SVG, встроенных в XHTML. Для нестандартного раздела используется указанный в книге запасной XHTML или SVG. Текст внутри растровых изображений и защищённые DRM-книги не поддерживаются.

## Глоссарий для фанфиков

Подготовьте UTF-8 JSON со своими соответствиями.

```json
{
  "哈利": "Гарри",
  "哈利·波特": "Гарри Поттер",
  "赫敏": "Гермиона",
  "霍格沃茨": "Хогвартс"
}
```

Передайте этот файл как `--glossary canon.json`. При автоматическом сборе введённые формы сохраняются в итоговом словаре и передаются модели при каждом совпадении. Модель склоняет имена по правилам русского языка. Новые варианты стоит просмотреть, особенно если у произведения несколько русских локализаций.

Поле `aliases` объединяет несколько китайских написаний под одним русским именем. При изменении перевода или списка склонений правится одна запись. Каждое написание принадлежит одной записи. Автосбор учитывает варианты как уже утверждённые термины.

По умолчанию объект включает проверку форм в переводе и редактуре. Добавьте допустимые склонения в `forms`. Если запись нужна как подсказка, задайте `"strict": false` и пропустите `forms`. Строковые записи также служат подсказками. При совпадении двух обязательных записей с одной позиции применяется более длинная. Обязательная форма сохраняет приоритет перед подсказкой. Проверка форм отслеживает имя в пределах блока, а смысл сцены требует отдельной вычитки.

```json
{
  "哈利": {"ru": "Гарри"},
  "赫敏": {
    "ru": "Гермиона",
    "aliases": ["妙丽", "妙麗"],
    "forms": ["Гермионы", "Гермионе", "Гермиону", "Гермионой"]
  }
}
```

```bash
# Предложить недостающие имена и термины.
uv run ai-translator glossary "книга.epub" --glossary canon.json -o review.json

# Внести правки в review.json и использовать готовый словарь.
uv run ai-translator translate "книга.epub" --glossary review.json --no-auto-glossary --edit
```

При обычном переводе глоссарий автоматически собирается перед переводом. Чтобы сохранить его, укажите `--save-glossary review.json`.

## Проба одной главы

В CLI список глав и план пробы можно получить без входа к провайдеру. Список показывает идентификаторы вида `2@8f3b677129efa01d`. Скопируйте идентификатор нужной главы целиком, чтобы привязать выбор к текущей книге и кодировке.

```bash
uv run ai-translator inspect "книга.epub" --list-chapters
# Подставьте идентификатор своей главы из списка.
chapter_ref="2@8f3b677129efa01d"
uv run ai-translator inspect "книга.epub" --for sample --chapter "$chapter_ref" --edit
uv run ai-translator sample "книга.epub" --chapter "$chapter_ref" --edit
```

Шаблон `книга.chapter-2.sample.ru.txt` выделяет результат главы в отдельный файл. Команда `--chapter` берёт все пакеты главы и используется отдельно от `--start-batch` и `--batches`. Краткая форма `--chapter 2` выбирает текущую главу № 2 без привязки к ревизии книги. Повтор той же пробы может использовать принятые ответы из кеша.

В EPUB используются ссылки из NAV, включая якоря внутри XHTML и SVG. Ссылки из NCX дополняют NAV и используются самостоятельно, если NAV отсутствует. Для совпадающих ссылок сохраняется название из NAV. При неполном оглавлении границы могут дополнить нумерованные заголовки и заголовки того же уровня, что и главы из оглавления. При отсутствии пригодных ссылок используются заголовки или границы документов. В FB2 можно выбрать отдельную главу, раздел с вложенными главами или весь том по его заголовку. В TXT распознаются короткие строки с нумерацией вроде «第二章», «第二章：石门» и «第二章（下）». Для книги без распознанных глав можно выбрать пробу по пакетам.

Если изменилась книга, её кодировка или правила разбивки на главы после обновления программы, загрузите оглавление заново и повторите выбор.

## Модели и стиль

Сохраните параметры в `translation.toml` и добавьте `--config translation.toml` к нужной команде. Модель и reasoning задаются независимо для каждого этапа. Имена должны быть доступны выбранному провайдеру и вашей учётной записи. Значение `reasoning = ""` оставляет настройку провайдеру.

```toml
fandom = "Гарри Поттер"
style = "Естественная русская проза. Голоса героев различимы. Используй ё."
batch_chars = 2400
timeout = 300

[glossary]
model = "gpt-6.2-sol"
reasoning = "low"

[translate]
model = "gpt-6.2-sol"
reasoning = "low"

[edit]
model = "gpt-6.2-sol"
reasoning = "medium"
```

Команда `sample` сохраняет двуязычную пробу в TXT. По умолчанию она переводит первый пакет, а `--batches` позволяет взять больше. Запустите её с двумя конфигурациями и разными выходными путями, чтобы сравнить стиль до перевода всей книги.

`sample --json-events --sample-pairs` добавляет пары фрагментов в поток событий после успешного сохранения пробы. Поля `original` и `translation` события `sample_pair` содержат текст, включая внутренние переносы строк.

При включённой редактуре добавьте `--sample-versions`, чтобы получить поля `draft`, `edited` и `review_choice` в тех же событиях. `review_choice` принимает значение `draft` или `edited`, когда сверка выбрала готовый вариант, `repaired`, когда она исправила блок, и `null`, когда сверка не принимала решение по блоку. Запросы к моделям и содержимое выходного TXT остаются теми же.

Чтобы начать с другого пакета, добавьте `--start-batch N`. Оценка запросов покажет начало и конец выбранного диапазона. При старте с середины книги первый пакет получает китайский контекст предыдущих абзацев без отдельного запроса. При полном прогоне вместо него используется предыдущий перевод, поэтому ключ кеша может различаться.

Если важна дополнительная сверка после редактуры, используйте `--edit --review-edits` или включите «Сверять редактуру с оригиналом» в окне. Модель сравнит исходник, черновик и редактуру и выберет одну из двух уже проверенных версий каждого изменённого блока. На пакет с изменениями обычно нужен один дополнительный запрос. Некорректный ответ может потребовать одного повтора. Следующий редакторский запрос использует выбранный текст как контекст. Для сверки можно отдельно задать модель и reasoning в разделе `[review]` TOML или на вкладке «Модели и стиль». Сверка помогает выявлять потери смысла, но может пропустить ошибку, особенно если она есть в обеих версиях.

Чтобы сверка могла исправлять ошибки в обоих вариантах, используйте `--edit --repair-review` или дополнительно включите «Исправлять общие ошибки при сверке». Этот режим проверяет каждый пакет, включая совпадающие версии. Обычно нужен один запрос сверки на пакет. При отклонении ответа возможен один повтор. Исправленный текст проходит те же проверки разметки и обязательных форм глоссария, что и перевод. В пробе итог можно сравнить с обоими исходными вариантами.

```bash
uv run ai-translator sample "книга.epub" --config translation.toml --batches 2 \
  --glossary canon.json --no-auto-glossary --edit -o "проба.txt"
```

С готовым глоссарием и `--no-auto-glossary` полный прогон переиспользует ответы из пробы при тех же настройках. Автоматический глоссарий пробы охватывает только выбранные пакеты. Его можно сохранить через `--save-glossary`. При полном сборе состав словаря и разбиение могут измениться.

`inspect` показывает число блоков, пакетов и план запросов без обращения к модели. При существующей базе команда проходит по кешу в порядке реального запуска. Если все ответы подходят, запуск покрыт кешем. Иначе отчёт покажет проверенные совпадения и этап первого нового запроса. При полном переводе с автоглоссарием план остаётся предварительным, пока сбор терминов не покрыт кешем. Когда все термины доступны, расчёт учитывает новое разбиение. Короткие разделы могут обрабатываться в одном пакете. По умолчанию на пакет приходится один запрос на сбор глоссария и один на перевод. `--no-auto-glossary` пропускает сбор терминов, `--edit` добавляет запрос на редактуру. Если ответ нарушил разметку или пропустил блок, переводчик один раз запрашивает исправление.

```bash
uv run ai-translator inspect "книга.epub" --config translation.toml --edit
uv run ai-translator inspect "книга.epub" --for sample --start-batch 2 --batches 1
uv run ai-translator translate "книга.epub" --config translation.toml --edit --max-calls 20
```

`--max-calls` ограничивает число новых запросов за запуск, включая запросы на исправление. При лимите в один запрос исправление будет отправлено на следующем запуске. Статистика токенов появляется, если провайдер вернул её. Готовые ответы сохраняются в скрытой базе SQLite рядом с исходником. После остановки по лимиту или ошибке подключения повторите исходную команду. Меняя только модель редактора, можно переиспользовать черновик. Передавайте `--state путь.sqlite3`, если нужно хранить базу отдельно. Для замены уже существующего результата укажите `--force`.

`--max-total-calls 30` задаёт общий лимит в SQLite, который действует и при следующих запусках. Сбор глоссария, перевод, редактура и сверка используют один счётчик, если у них общая база. Это касается и двуязычных проб. Кешированный ответ не расходует лимит. Попытка записывается перед отправкой, поэтому счётчик включает неудачные и прерванные запросы. Он считает обращения переводчика к провайдеру. Токены и внутренние повторы провайдера учитываются отдельно его сервисом. Для старой базы начальное значение равно числу сохранённых ответов, поскольку более ранние неудачные попытки неизвестны. `inspect` покажет счётчик и лимит. `--max-total-calls -1` снимает лимит без сброса счётчика. `--tighten-total-calls 30` применяет меньший из 30 и уже сохранённого потолка. Десктоп использует тот же режим «Ужесточить» при восстановлении прерванной записи.

Если процесс прервался при сохранении книги и глоссария, повторите запуск с теми же выходными путями. Сначала программа проверит журнал и нужные резервные копии. Новые журналы содержат контрольные суммы копий, старые журналы читаются без проверки содержимого копий. При повреждении журнала или копии либо при её утрате программа остановится до изменения выходных файлов и запросов к модели и покажет путь к файлу восстановления.

Программа синхронизирует данные выходных файлов до замены и, где файловая система позволяет открыть и синхронизировать каталог, закрепляет переименования до фиксации журнала. При откате копии хранятся до синхронизации восстановленных путей. Тесты воспроизводят остановку процесса и ошибки синхронизации.

Если служебное имя превышает лимит файловой системы, кеш размещается в папке `.ai-translator-cache` рядом с книгой, а служебные файлы сохранения — в `.ai-translator-publication` рядом с выходным файлом. Прежняя непустая база при первом запуске копируется через SQLite вместе со счётчиком запросов. После переноса используется новая база. При необходимости имя результата по умолчанию сокращается с сохранением расширения. Явно выбранный выходной путь используется как указан.

## Claude Pro

Установите актуальный Claude Code и выполните `claude auth login`, выбрав вход через Claude.ai. Переводчик вызывает установленный CLI в режиме `claude -p` с локальным входом и структурированным выводом. По умолчанию для глоссария используется Haiku, для перевода и редактуры — Sonnet. Имена моделей и `reasoning` передаются как `--model` и `--effort`. [CLI Claude Code](https://code.claude.com/docs/en/cli-reference) · [Использование лимитов подписки](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)

Для запуска требуются флаги `--safe-mode` и `--setting-sources`. Проверка входа испытана с официальным CLI 2.1.311 без аккаунта. Если установленный CLI не распознаёт флаги, команда `doctor` предложит обновление.

```bash
uv run ai-translator sample "книга.epub" --provider claude-code --edit --max-calls 3
```

## Google Antigravity

Установите [Antigravity CLI](https://antigravity.google/docs/getting-started?tab=cli), один раз запустите `agy` и выберите Google OAuth для входа в личный аккаунт. В Desktop выберите «Google через Antigravity». В CLI используется `--provider antigravity`. После входа перевод, редактура, глоссарий и сверка выполняются автоматически. Переводчик передаёт текст через stdin и читает структурированный ответ Antigravity.

```bash
uv run ai-translator doctor --provider antigravity
uv run ai-translator sample "книга.epub" --provider antigravity --no-auto-glossary --edit --max-calls 2
```

Проверка входа запускает Antigravity без запроса к модели. Если клиент завершится без статуса входа, переводчик сообщит, что вход не удалось подтвердить. При явном отказе авторизации перевод остановится до учёта первой попытки.

Пример переводит и редактирует один пакет без автосбора глоссария. Если лимит закончится при исправлении ответа, команда вернёт код 3. Повтор той же команды использует уже принятые ответы из кеша.

В профиле TOML можно задать `provider = "antigravity"` и настройки модели и reasoning каждого этапа. Идентификаторы моделей для своего аккаунта показывает `agy models`. По умолчанию выбран Gemini 3.8 Flash. Параметр использования дополнительных кредитов отключён в настройках запуска переводчика. Доступность моделей и объём квоты зависят от аккаунта. Запуск и отказ без входа проверены с CLI 1.5.13. Успешный перевод проверен на заглушке, вход с Google AI Plus пока не испытан. [Тарифы Google AI](https://one.google.com/intl/en/about/google-ai-plans/) · [Документация headless-режима](https://antigravity.google/docs/cli/headless/)

## Проверки

```bash
uv run --locked python -m unittest discover -s tests -v
QT_QPA_PLATFORM=offscreen uv run --locked --extra desktop python -m unittest discover -s tests -v
```

Для проверки формата готового EPUB используйте `java -jar epubcheck.jar книга.ru.epub`. Проверка схемы и ссылок дополняет открытие книги в читалке. [EPUBCheck](https://github.com/w3c/epubcheck)

Перед отправкой текста проверяется размер книги. Пределы для исходных TXT и FB2 составляют 32 и 128 МиБ. Для EPUB предел составляет 512 МиБ распакованных данных, 20 000 ресурсов, 16 МиБ для каталога ZIP и 128 МиБ суммарно для разбираемой разметки.

Вывод Codex и Claude Code ограничен 16 МиБ для stdout и 2 МиБ для stderr. При проверке входа предел составляет 256 КиБ на поток. Переводчик получает итоговое сообщение Codex из ограниченного потока JSONL. На Windows дерево процессов провайдера помещается в Job Object, который закрывается при выходе рабочего процесса. Если вложенную группу создать нельзя, приложение пробует запустить свою группу отдельно. Если Windows запрещает и этот вариант, попытка завершается до запуска провайдера с сообщением об ошибке. [События Codex CLI](https://learn.chatgpt.com/docs/non-interactive-mode) · [Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)

Тело ответа OpenAI API ограничено 16 МиБ. Тайм-аут общий для ожидания системного DNS, TCP, прокси, TLS и чтения ответа. Системный резолвер может продолжить работу после тайм-аута. Приложение допускает до двух таких поисков адреса одновременно на свой процесс и завершает попытку до отправки текста, если срок ожидания истёк.

В GitHub Actions wheel устанавливается с зафиксированными зависимостями. Точки входа и тесты CLI и Qt проверяются без дисплея на Linux, macOS и Windows с Python 3.11 и 3.12. В задании Linux с Python 3.12 отдельно проверяется установка `wheel[desktop]` вне репозитория и выполняются десктопные тесты через Qt/X11 на виртуальном дисплее. Тесты используют локальную заглушку Codex и не требуют аккаунта.

Коды CLI: `0` — успех, `1` — ошибка файла, настроек или провайдера, `3` — достигнут лимит запросов текущего запуска или общий лимит, `4` — проблема авторизации, `130` — отмена. Ошибки синтаксиса команды используют код `2`. `--json-events` выводит события в JSON Lines для программной обработки. Данные и диагностика в стандартных потоках записываются в UTF-8. Команда `doctor --provider codex` проверяет вход без перевода.
