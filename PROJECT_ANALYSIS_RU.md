# AI Translator — аудит и план реализации

**Решение для первого релиза.** Начать с двух задач: показать читателю план и результат запуска вне журнала, затем добавить поиск и просмотр границ в существующее оглавление. Обе улучшают путь от выбора книги до первой осмысленной пробы. Для них уже есть данные, тестовый контур и единый CLI. Следующее по ценности заимствование — навигация по фрагментам, которые стоит вычитать. Физическое разрезание книги и очередь рабочих процессов потребуют других продуктовых решений.

Приоритеты ниже — инженерная оценка для сценария «один читатель переводит длинную китайскую книгу на русский». Данных о частоте пользовательских действий нет. ## Что подтверждено запуском

- **Номер записи и номер в заголовке действительно расходятся.** Для TXT из пяти строк `序言 / 第一章 初遇 / 春雨落下。 / 第二章 回家 / 我回来了。` команда `inspect --list-chapters` вернула «Начало книги» и две главы, с 1, 2 и 2 блоками. Запрос `inspect --for sample --chapter 2` выбрал **первую** именованную главу, показал начало и конец и рассчитал два обращения без кеша при включённом автоглоссарии. В списке стоит показывать заголовок крупнее порядкового номера.
- **Пустой результат выглядит успешным.** На UTF-8 TXT с единственной строкой `Hello` команда `translate --max-calls 0 --json-events` завершилась с кодом 0, сообщила о нуле обращений, выдала `notice` и путь к созданному `.ru.txt`. В GUI событие `notice` уходит в журнал, а успешное завершение показывает «Готово». Это повод уточнить итог в окне с сохранением совместимости CLI.
- **Стоимость осмотра зависит от числа блоков.** В синтетическом TXT на 1 000 глав заголовок каждой имел вид `第N章 回家`, за ним шли 100 строк `窗外的春雨落下了。`. Размер UTF-8 — 2 816 893 байта. На Linux с Python 3.12.3 одиночный холодный по кешу ответов прогон `inspect --list-chapters` занял 1,09 с и 102 976 КиБ пикового RSS, а `inspect --no-auto-glossary` — 1,84 с и 112 504 КиБ для 101 000 блоков и 1 579 пакетов. Измерение через GNU time включает старт процесса. Это контрольный пример, по которому можно сравнивать изменения на одной машине. Форматы EPUB и FB2 требуют отдельных измерений.
- **Автотесты.** Итог на Ubuntu 24.04, Python 3.12.3, Qt offscreen — 201 тест прошёл, 2 Windows-специфичных теста пропущены, ошибок нет (76,36 с). Для загрузки Qt библиотека EGL подключалась из распакованного во временную папку пакета Ubuntu.
- **Границы проверки.** Исходники обоих проектов, документация и CI просмотрены статически. Локально проверялись наш CLI и сценарии автоматических тестов. Живые модельные сервисы и GUI форка не запускались. По этим данным можно оценить сохранность структуры, путь пользователя и восстановление. Для сравнения литературного качества моделей потребуется слепая вычитка одинаковых сцен.

## Задания для реализации

Порядок соответствует предлагаемой поставке. Размер S означает локальное изменение одного сценария, M — согласованное изменение нескольких частей, L — новый контракт данных или выходного файла. Это относительная трудоёмкость. Каждый пункт допускает отдельную поставку.

### 1. Показать план до запуска и объяснить его итог · первый релиз · M

**Сценарий.** Читатель нажал «Оценить запросы» и хочет понять, хватит ли лимита на пробу. Сейчас `_read_events` получает структурированные значения `plan`, `cache_replay`, `inspection` и `sample_range`, но для этих событий отображает текст в журнале. Расчёт в `cli._run` уже различает предварительный план и гарантированный префикс кеша.

**Изменение.** Добавить в GUI компактную сводку по последней оценке: операция и область, включённые этапы, запросы без кеша и повторов, сколько ответов удастся воспроизвести до первого промаха, действующий общий потолок при наличии. Помечать предварительный план после автосбора и условную сверку. При смене исходника, главы, диапазона, модели, стиля, словаря, кеша или параметров обработки помечать оценку устаревшей. При завершении показать факт из `requests` и `usage`, при нуле блоков — явное «Китайский текст не найден» и фактический путь результата. Сохранить журнал и возможность запустить перевод напрямую.

**Приёмка.** На пустом кеше, частичном кеше, полностью покрытом запуске и при `--max-calls 0` сводка различает план, доступный бюджет и реальный расход. Записи в базе от другой конфигурации не уменьшают план арифметически. Повторная оценка сама не вызывает провайдера и не меняет бюджет. Проверить ввод с клавиатуры, читаемость при минимальном размере окна и смену профиля после оценки. Сценарии — [desktop](tests/test_desktop.py) и [CLI](tests/test_translator.py).

### 2. Сделать оглавление удобным для длинных книг · первый релиз · M

**Сценарий.** В книге на тысячу глав нужно быстро найти «回家», увидеть границы и взять пробу. Сегодня `Window._set_chapters` заполняет QComboBox номером и заголовком. CLI уже выдаёт `units`, `reference`, `revision`, а границы выбранной главы возвращает `inspect --for sample --chapter`.

**Изменение.** Добавить поиск по части заголовка и номеру записи, число совпадений, количество блоков и действие «Показать границы». Вариант «По пакетам» оставить доступным при пустом каталоге. Фильтровать полученный каталог в памяти. Границы загружать для выбранной записи через существующий рабочий процесс. Не запускать новый разбор книги на каждую клавишу. Ключ выбора — номер записи исходного каталога и ревизия, включая кодировку TXT. У одинаковых названий должны различаться номера. Название «Глава 1» внутри книги может относиться к записи 2.

**Приёмка.** Поиск и выбор клавиатурой по 1 000 записям, две записи с одним названием, предисловие, TXT без заголовков, EPUB с несколькими якорями в одном XHTML, вложенные разделы FB2. После обновления книги выбор требует обновить каталог. Показанные первый и последний блок совпадают с `inspect`. Запись прежнего формата из QSettings восстанавливается. Существующие тесты про смену книги и устаревшую главу продолжают проходить. [Каталог](src/ai_translator/formats.py) · [Команды и проверки ревизии](src/ai_translator/cli.py) · [GUI](src/ai_translator/desktop.py)

### 3. Вести вычитку по изменениям · следующий релиз · S для пробы, L для книги

**Первый шаг.** В `SamplePreview` дать действие «К следующему изменению». Режим «Редактура изменила текст» использует `draft != edited`, режим «Сверка исправила» — `review_choice == "repaired"`. Показать число совпадений и текущий номер в исходной пробе. Пользователь должен видеть оригинал и итог и при необходимости сравнить две версии. Проба уже получает эти значения через `sample_pair`; повторное обращение к модели лишнее.

**Для полной книги.** После проверки востребованности пробы добавить опциональную сводку с адресом места в исходнике (ревизия, секция, блок, часть блока), этапом, причиной и статусом. Координаты назначать до разбиения и замены текста. Учитывать блоки вне сюжетных глав. Литературный выбор одной из двух версий показывать как решение сверки. Отклонённый ответ мог быть исправлен повторной попыткой, а отсутствие замечаний возможно и при выключенной сверке. Отчёт о завершённом запуске показывать только после успешной публикации. Если нужен файл отчёта, согласовать независимый экспорт из итоговых данных либо расширить транзакционную запись с отдельной проверкой восстановления.

**Приёмка.** На паре без изменений, возврате к черновику, принятой редактуре и исправленном варианте фильтр ведёт на нужный фрагмент. При выключенной редактуре управление описывает этот режим. При воспроизведении из кеша результаты совпадают, новых обращений и различий в итоговой книге нет. Большой отчёт загружается порциями. [Выбор версии](src/ai_translator/pipeline.py) · [Отображение пар](src/ai_translator/desktop.py)

### 4. Расширить работу с главами только при отдельной потребности · после задачи 2 · M–L

Есть два разных запроса читателей. Если заголовки TXT распознаны неверно, полезна **ручная карта границ**. Если главы найдены правильно, но нужны для чтения вне программы, полезен **экспорт выбранного фрагмента**. На первом релизе достаточно узнать, который из сценариев встречается на реальных книгах.

- **Карта TXT.** Предложить предварительный список с первыми строками и действием «Начать главу здесь». Якорь — строка декодированного исходника с ревизией и кодировкой. Граница может находиться на строке без Han, хотя переводимые блоки строятся только из строк с Han. Сохранять карту отдельно по явному действию. Проверить пустые строки, предисловие, CRLF, GB18030, повторяющиеся заголовки, снятие границы и отказ применять устаревшую карту. Каталог должен давать те же границы в CLI и GUI.
- **Выбор нескольких глав.** Самый узкий полезный результат — один двуязычный TXT по выбранным главам в порядке книги. Предлагаемый интерфейс — повторяемый выбор для `sample` и идентичный выбор для `inspect --for sample`. Расширять после проверки задачи 2. Нормализовать пересечения `Chapter.spans`: в FB2 родитель может содержать дочерние разделы. Разорванные диапазоны требуют отдельного контекста, их нельзя склеить как соседние главы. Проверить одинаковые заголовки, смену ревизии, дедупликацию блоков, имя результата, единый лимит, остановку и повтор.
- **Отдельный EPUB/FB2 главы** требует продуктовой спецификации для метаданных, оглавления, сносок, перекрёстных ссылок и ресурсов. Текущий `Book.write` пишет книгу целиком, а чтение уже подготавливает языковые метаданные к переводу. Подстановка выбранных `spans` в полный перевод сама по себе даст смешанный результат. Для нового экспортёра потребуются фикстуры, открывающиеся в читалке, и проверка ссылок. Стоимость этой ветки существенно выше поиска и пробы.

### 5. Упростить возврат к книге и работу со словарём · кандидаты · M каждый

**Недавние запуски.** Расширить `lastRun` до ограниченной истории локальных снимков. В строке показать книгу, операцию, время и путь результата. «Продолжить» восстанавливает параметры и позволяет оценить актуальный кеш. Использовать существующие проверки ревизии, публикации и ужесточения общего лимита. Миграция читает старую единственную запись. Проверить удалённый источник, переименованный файл, две одноимённые книги в разных папках, очистку истории без удаления переводов, а также общий лимит, который CLI снизил после сохранения снимка. Автоматический старт очереди — отдельное решение.

**Контекст термина.** Начать с действия в пробе «Открыть термин в словаре». Показывать форму оригинала, русский вариант и текущую пару. Переиспользовать `parse_glossary`, `expand_glossary` и `GlossaryDialog`. Правка действует при следующем явном запуске. Проверить алиас, склонение, отмену сохранения и коллизию пути. Сохранённая проба должна оставаться читаемой в том виде, в котором была опубликована. ## Производительность, качество и поставка

1. **Измерить память до изменения архитектуры.** Сейчас чтение TXT материализует строки и объекты Unit, а CLI строит список всех пакетов. Для каталога стоимость полного чтения наблюдается даже без вызова модели. Снять по три замера времени и пикового RSS для каталога, одной главы и полного осмотра на одинаковых TXT/FB2/EPUB. При подтверждённом узком месте первый кандидат — облегчённое чтение каталога TXT без создания функций обратной записи на каждую строку. Сравнить названия, порядок, блоки и ревизии с текущим парсером. Считать отдельно задержку поиска по уже открытому каталогу. Не переносить выводы синтетического теста на реальную скорость моделей.
2. **Сохранить воспроизводимость и бюджет.** При расширении UI потреблять структурированные события. Для новых полей использовать добавления, старые имена и типы оставить доступными. Повтор перевода после изменения стиля, глоссария или окружения соседних фрагментов может породить другой запрос. Проба главы поэтому не гарантирует экономию ровно такого же числа пакетов полной книги. Тестировать расход по фактическим вызовам фальшивого провайдера, в том числе при прерывании и коррекции невалидного ответа.
3. **Проверить литературный эффект отдельно.** Для изменений промптов или межглавной согласованности подготовить небольшой разрешённый корпус со сценой диалога, несколькими формами имени, числом, примечанием и повторным появлением персонажа в следующей главе. Рецензенту давать одинаковый оригинал и две версии вслепую. Считать пропуски смысла, нарушения терминологии и предпочтение читателя по сценам. Фиксировать профиль, режим редактуры, число запросов и доступную статистику токенов. Изменения GUI можно принимать независимо от такого исследования.
4. **Обслуживаемость.** В момент реализации задач 1–2 выделять из большого `Window` только конкретные элементы интерфейса, например представление плана. Оставить управление процессом и публикацией у текущих владельцев. Чистую модель результата можно тестировать без Qt. Для изменений CLI прогнать тесты контрактов всех четырёх адаптеров. Существующая CI-матрица собирает wheel, проверяет две команды входа, Python 3.11/3.12 на трёх ОС, Qt offscreen и дополнительный X11-прогон. [Настройки пакета](pyproject.toml) · [CI](.github/workflows/test.yml) · [Контракты провайдеров](tests/test_provider_contracts.py)
5. **Первый запуск.** Короткая дорожка в README: открыть книгу → проверить вход → оценить пробу → перевести и сравнить → запустить всю книгу. Для сообщения о `libEGL.so.1` дать пользователю Ubuntu 24.04 указание на пакет `libegl1`, который устанавливает и CI. Полный набор системных зависимостей зависит от режима дисплея. Практическая проверка UX — дать читателю незнакомую книгу, попросить выбрать вторую именованную главу, объяснить ожидаемые обращения и найти первую правку. Записать время, ошибочный выбор и места, где пришлось читать журнал. Сопоставить с тем же сценарием после задач 1–3.

## Передача агенту

Первый инкремент — задача 1. Затем задача 2 отдельным изменением. Для каждой добавить прицельную регрессию в существующий набор и обновить соответствующий пользовательский сценарий README. Для задачи 3 сначала выпустить фильтр в пробе. Решение о полном отчёте, ручной карте TXT или пакетном экспорте принимать по результатам вычитки и примерам книг. Это позволяет начать разработку без новой БД проектов, изменения формата книг и дополнительных обращений к модели.

Команды для проверки из корня репозитория при установленных зависимостях:

```bash
uv sync --locked --extra desktop
QT_QPA_PLATFORM=offscreen uv run --no-sync python -m unittest discover -s tests -v
uv run --no-sync ai-translator inspect --list-chapters "книга.txt"
uv run --no-sync ai-translator inspect --for sample --chapter 2 --json-events "книга.txt"
```

В последней команде число 2 означает вторую запись актуального каталога. Для сохранённого выбора передавать целиком выданный идентификатор с ревизией.
